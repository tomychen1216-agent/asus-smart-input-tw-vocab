本專案提供為「華碩智慧輸入法（ASUS Smart Input）」量身打造的**完整自訂個人詞庫（1,384 筆在地專業詞彙）**、**自動化格式轉換腳本**，以及解決「成功 0 筆、失敗整批退件」的**完整逆向工程排錯歷程**。

華碩官方常見問題說明文件（[FAQ 1048635](https://www.asus.com/tw/support/faq/1048635/)）僅提及支援「純文字 UTF-8」匯入，但在實際操作中，純中文文字檔會遭遇 100% 退件。本專案將官方底層未公開的驗證規格、台灣教育部發音校驗標準徹底解密，讓使用者可直接匯入現成詞庫，或利用腳本將任意自訂詞單秒級轉為相容格式。

## ⚡ 快速開始 (Quick Start)

### 方法一：直接匯入已校驗完成的 1,384 筆現成詞庫 (推薦)

本儲存庫已包含經台灣教育部標準校準、完全符合華碩原子性格式的完整詞庫檔案：[`asus_tw_vocab_ready.txt`](asus_tw_vocab_ready.txt)。

1. 下載儲存庫中的 [`asus_tw_vocab_ready.txt`](asus_tw_vocab_ready.txt)。
2. 在 Windows 桌面右下角工作列的「華碩智慧輸入法」圖示按右鍵，進入 **「設定」 $\to$「個人詞庫」**（或於「教學與設定」中開啟詞庫管理）。
3. 點選視窗左下方的 **「匯入」** 按鈕。
4. 選取下載的 `asus_tw_vocab_ready.txt` 檔案，確認匯入完成。

> [!NOTE]
> 匯入完成後，若提示有數百筆詞彙「失敗」，請勿驚慌！這是華碩輸入法的「出廠詞庫自動去重保護機制」（詳見後文剖析），代表該詞早已內建於輸入法核心，不會重複占用您寶貴的自訂詞庫額度。

---

### 方法二：利用 Python 腳本自訂轉譯詞彙

如果您有一份自訂的純中文詞單（每行一詞，如 `my_words.txt`）：

```bash
# 1. 安裝注音解析相依套件
pip install pypinyin

# 2. 執行轉換腳本
python convert_asus_vocab.py my_words.txt
```

執行後將自動產出 `asus_ready_my_words.txt`，直接依上述步驟匯入華碩輸入法即可。

## 🛑 官方未明說的底層規格與隱藏限制

華碩輸入法的匯入模組具備嚴格的原子性檢查，只要有一處格式偏離即會引發單筆或整批失敗：

### 1. 檔案與詞彙邊界限制
- **總筆數硬性上限**：**2,500 筆**。若來源檔大於 2,500 筆（例如實測時初版的 4,399 筆），系統不會截斷前 2,500 筆，而是直接觸發整批退件（顯示「成功 0 筆、失敗 4399 筆」）。
- **單詞長度嚴格限定**：**2 至 9 個繁體中文字**。單字（1 字）或超過 9 字（如「地籍圖資網路便民服務」）均會被視為非法格式。
- **純中文字元限制**：嚴禁混雜英文字母、半形/全形英數數字、空格與標點符號。
- **檔案編碼**：必須為 **UTF-8（無 BOM 佳）**。Windows 記事本有時自動附加的 BOM 標頭（`\xEF\xBB\xBF`）會導致首行詞彙解析失效。

### 2. 反向工程揭露的格式標準
華碩輸入法匯入引擎**不具備自動斷詞與拼音關聯能力**，每一行資料必須嚴格遵循鍵值對結構：

$$\text{[詞彙]} + \text{[兩個半形空格]} + \text{[連續注音符號]}$$

範例：
```text
邊緣運算  ㄅㄧㄢˉㄩㄢˊㄩㄣˋㄙㄨㄢˋ
伺服器  ㄙˋㄈㄨˊㄑㄧˋ
電子發票  ㄉㄧㄢˋ˙ㄗㄈㄚˉㄆㄧㄠˋ
```

| 格式項目 | 規格標準 | 違規錯誤後果 |
| :--- | :--- | :--- |
| **分隔符號** | **恰好兩個半形空格**（`\u0020\u0020`） | 使用單一空格、Tab 鍵或全形空格，會整行被判定為無效格式。 |
| **注音連續性** | 全詞注音連寫，**字與字之間不得有任何空格** | 寫成 `ㄅㄧㄢˉ ㄩㄢˊ` 會無法解析。 |
| **一聲標記** | 第一聲**必須顯式加上橫線符號 `ˉ`**（Unicode `\u02C9`） | 一般注音常省略一聲，但華碩若無 `ˉ` 會判定為未拼完而拋棄。 |
| **輕聲位置** | 輕聲點 `˙`（Unicode `\u02D9`）**必須置於音節最前端** | 寫在字尾如 `ㄗ˙` 會退件，必須為 `˙ㄗ`。 |
| **發音規範** | 必須 100% 相容**台灣教育部 (MOE) 標準字典** | 大陸發音（如伺服器 `cì`）直接被退件。 |

## 🚧 排錯歷程與六大關卡深度剖析 (Troubleshooting Case Study)

在建構本詞庫的實戰中，共逆向排查了 6 個核心技術問題：

```mermaid

    C --> D{"關卡 2：PowerShell 寫檔報錯 UnauthorizedAccess"}
    D -->|原因：WriteAllLines 預設寫入 System32| E["在路徑前明確指派 $PWD 當前目錄"]
    E --> F{"關卡 3：純文字檔案匯入依舊 100% 失敗"}

    N --> O["最終達成：1,384 筆長尾專有名詞 100% 匯入，額度最佳化"]
```

### 關卡 1：4,399 筆整批阻擋（筆數超限與超長詞）
- **現象**：匯入 4,399 行的文字檔，跳出「成功 0 筆、失敗 4399 筆」。
- **根因**：華碩詞庫設有 2,500 筆上限，解析時行數大於 2,500 會整批退回；且內含 10 字以上的超長詞（如「地籍圖資網路便民服務」）。
- **解法**：使用 PowerShell 進行資料清洗，過濾字數在 2~9 字之間、去除重複項，並截取前 2,200 筆。

### 關卡 2：PowerShell 的 System32 權限陷阱
- **現象**：執行 `[System.IO.File]::WriteAllLines("output.txt", ...)` 出現 `UnauthorizedAccessException`。
- **根因**：.NET 的靜態方法若無絕對路徑，預設目錄為 `C:\WINDOWS\system32`。
- **解法**：在檔名前明確加上 `$PWD` 變數：`"$PWD\output.txt"`。

### 關卡 3：純文字 100% 失敗與 BOM 盲點
- **現象**：清洗後的純中文 UTF-8 檔案，依然「成功 0 筆、失敗 2200 筆」，嘗試轉換為帶 BOM 的 UTF-8 依然失敗。
- **突破**：在輸入法介面手動新增一筆詞彙並點選「匯出」，取得系統出廠的 `UserDictionary.txt`。以編輯器檢視發現格式為 `[詞]  [注音]`，證實輸入法不會自動拼音，必須事前注入完整注音。

### 關卡 4：819 筆退件（兩岸字音差異與輕聲倒置）
- **現象**：使用 `pypinyin` 自動產生注音後，成功 1,381 筆，退件 819 筆。
- **根因**：
  1. **兩岸發音差異**：`pypinyin` 預設採用大陸普通話拼音，與台灣教育部標準分歧（如「伺服器」大陸為 `cì`，台灣為 `ㄙˋ`；「除息」大陸為 `xī`，台灣為 `ㄒㄧˊ`；「品質」大陸為 `zhì`，台灣為 `ㄓˊ`；「企業」大陸為 `qǐ`，台灣為 `ㄑㄧˋ`；「微軟」大陸為 `wēi`，台灣為 `ㄨㄟˊ`；「垃圾」大陸為 `lājī`，台灣為 `ㄌㄜˋ ㄙㄜˋ`）。華碩輸入法嚴格對照台灣教育部注音，注音不存在即剔除。
  2. **輕聲符號倒置**：`pypinyin` 輸出輕聲符號在字尾（如 `ㄉㄧㄢˋㄗ˙`），華碩只認可前置（`˙ㄗ`）。
- **解法**：在 Python 腳本中掛載 `taiwan_moe_dict` 強制覆寫表（涵蓋伺、期、息、質、微、危、企、垃、圾、署、崖等字），並用邏輯將 `˙` 移至音節首位。

### 關卡 5：檔名不符與 FileNotFoundError
- **現象**：使用者終端機路徑與腳本預設檔名不一致。
- **解法**：在 Python 腳本中加入多候選檔名自動偵測機制（支援 `a.txt`、`homophones.txt` 等）。

### 關卡 6：831 筆「失敗」的真相——華碩「出廠詞庫去重保護」
- **現象**：發音修正後再次匯入，依然顯示成功 1,369 筆、失敗 831 筆。
- **深度驗證**：將輸入法匯出的檔案 `export_dictionary_1.txt` 與來源詞庫交叉比對發現：
  - **被退件的 831 筆**：全數為日常極常見詞彙（`專案`、`程式碼`、`資料庫`、`牛肉麵`、`珍珠奶茶`、`一舉兩得`）。
  - **成功匯入的 1,369 筆**：全數為特定領域技術詞與在地複合詞（`邊緣運算`、`算力評測`、`交割結算基金`、`吃瓜群眾`）。
- **結論**：這是華碩的原廠保護邏輯，**系統出廠字典早已內建的日常詞彙會被直接跳過不匯入，以保護個人詞庫 2,500 筆的額度上限**。因此成功匯入一千多筆長尾詞，代表個人詞庫建置已達最佳狀態。
